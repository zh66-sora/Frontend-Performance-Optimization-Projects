#### 搜索*

```ts
const kwInput = ref('') // 输入框 v-model 直接绑这个，用户敲什么立刻显示什么
const keyword = ref('') // 延迟 200ms 后才从 kwInput 抄一份，只有它参与过滤

let kwTimer: number | undefined
watch(kwInput, (value) => {
  if (kwTimer !== undefined) window.clearTimeout(kwTimer)
  kwTimer = window.setTimeout(() => {
    keyword.value = value.trim().toLowerCase()
  }, 200)
})
```

#### 过滤*

```ts
const filtered = computed<CategoryNode[]>(() => {
  const kw = keyword.value
  const type = typeFilter.value
  if (!kw && type === 'all') return FIELD_CATEGORIES

  return FIELD_CATEGORIES.map((category) => {
    const groups = category.children
      .map((group) => ({
        title: group.title,
        children: group.children.filter(
          (field) =>
            (!kw || field.label.toLowerCase().includes(kw)) && (type === 'all' || field.type === type)
        )
      }))
      .filter((group) => group.children.length)

    return {
      ...category,
      children: groups,
      count: groups.reduce((sum, group) => sum + group.children.length, 0)
    }
  }).filter((category) => category.count > 0)
})
```

```
分类.map( → 小组.map( → 字段.filter( ) ).filter(空组) ).filter(空分类)
```

- **三层遍历** 筛选时要处理"分类 → 小组 → 字段"三层结构
- **无筛选条件，返回原数组** 默认状态下每次都返回**同一个数组引用**。Vue 的 `v-for` 渲染时判断"引用没变 → 数据没变，避免白做一轮 diff
- **filter** 小组或大类筛选完若空则直接清楚（视觉友好）

#### 滚动*

function onScroll() {

## 重点

### 选项懒加载优化 `defineLazy.ts`

> 懒加载在此项目内控制弹窗内标签选项是否应该存在。

```ts
// FieldSelector.vue
const LazyFieldList = defineLazy(FieldList, { perRow: 8, rowHeight: 30 })
```

它属于是高阶组件，接收FieldList这个组件，返回包含了懒加载逻辑的新组件。

**滚动传入**

```ts
export const SCROLL_ROOT: InjectionKey<() => HTMLElement | null> = Symbol('scroll-root')
```

供`FieldSelector` 用它把**滚动容器**往下传。且传的是函数 `() => scrollRef.value` ，确保调用时能获取最新值。且当前是深度层，直接使用 provide/inject

**懒加载参数**

```ts
export interface LazyOptions {
  /** 视口外多少像素就开始提前渲染，作为缓冲区 */
  rootMargin?: string
  /** 首次占位高度，防塌陷；不传则按字段数估算 */
  placeholderHeight?: number
  /** 每次渲染多少字段为一行，用于估算占位高度 */
  perRow?: number
  rowHeight?: number
}
```

#### 高阶组件的成本*

```ts
props: {
  fields, mode, tooltip, delay, pickedSet, onPick
}
```

```ts
h(component, { fields, mode, tooltip, pickedSet, onPick })
```

**`FieldList` 需要的参数，这里又原封不动声明了一遍。**上要接住所有参数，下要全部转手交出去。

#### 核心

```ts
if (进视口了) {
  先清掉定时器
  if (delay > 0) 等 delay 毫秒再显示内容
  else          立刻 show = true
} else {
  清掉定时器
  if (正在显示) {
    height = host.offsetHeight     ← 先把真实高度记下来
    show = false                   ← 再隐藏
  }
}
```

- **delay的意义** 当飞快往下滚时，内容往往撑不到delay结束就已经离开视口，这时直接取消该部分的渲染，提高快滚流畅程度；代价是慢滚时，会出现一定时间的区域白屏（delay没有结束）。
- **记录真实高度** 防止滚动条跳动/内容塌陷，视觉上无缝

### 浮层 `XTooltip.vue`

#### 浮层懒加载

```vue
<Teleport to="body">
  <div v-if="visible" class="x-popover" :style="posStyle">...</div>
</Teleport>
```

浮层挂载在body内，以免被滚动容器的滚动行为、overflow、z-index等影响。

且使用fixed定位，**mouseenter**时自行计算挂载位置再挂载。

|                      | 打开耗时 | DOM 节点 |
| :------------------- | :------- | :------- |
| 阶段 1（el-tooltip） | 1049 ms  | 4680     |
| 阶段 2（XTooltip）   | 350 ms   | **4680** |

阶段1、2的选择dom节点数是相同的；开销取决于是否使用el-tooltip，初始直接完成这套流程：

- 创建浮层 DOM（即使隐藏）
- 初始化定位/Popper 计算
- 绑定滚动、resize、等事件监听
- 初始化各类状态

#### 浮层内容canvas懒加载

等数据请求完毕，nextTick结束（Vue根据数据异步更新dom）后，再进行canvas绘制。不等nextTick会造成getContext报错。

#### 定时器与锁*

```
enter()   → 等 60ms 再显示（防闪烁）
leave()   → 等 80ms 再隐藏（预留鼠标的移动时间）
keepOpen()→ 鼠标进浮层时，取消那个 80ms 的关闭（防止阅读浮层时关闭）
```

#### 后续优化方向 监听

**监听是每个 `XTooltip` 实例各挂一个的。**2235 个字段 = 2235 个 `window` 上的 scroll 监听器。虽然 `hideNow` 一进去就 `if (visible)` 短路，但浏览器还是得在主线程上把这 2235 个回调**挨个调一遍**。

**可以在祖先组件（比如 `FieldSelector`）统一监听一次**，通过 provide 或者一个简单的回调集合分发给当前唯一可见的那个浮层。

### `createPromiseDialog.ts`

```
传统写法：组件里放 <el-dialog v-model="visible">，靠 visible 控制显隐
这里的写法：const result = await openSelector({ stage, selected })
```

本质是**编程式（命令式）动态创建弹窗应用**，优势是 `await` 一行拿结果、不污染原组件、按需创建用完销毁、可复用成通用弹窗 API；代价是脱离组件树、生命周期内部自行管理。适合**临时、低频**的弹窗场景。
